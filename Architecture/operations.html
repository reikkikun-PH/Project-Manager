04 — Running it

What it needs, what to keep, what to watch

The three things this computer cannot do alone, what a complete backup actually is, and the handful of behaviours that are deliberate but not obvious from the interface.

Outside services

Three things this computer cannot do by itself. Each is optional, and each has a fallback that keeps the app usable without it.

The public web address sharing

Starting the manager also asks Cloudflare for a free address on the internet that forwards back to your computer, and prints it so you can share it. The connection goes outward, so nothing is opened on your router and no port is exposed to the internet.

The address changes each time you start, so the app checks it really works before putting it on a page or in an email — you never share a link that has already died.

Without it: everything still works on this computer alone. You just cannot share the link with anyone else.

The email service notifications

Five kinds of message go out:

1. A six-digit sign-in code for a new user.  2. A new account signed up.  3. A new project is waiting for approval.  4. An admin request was approved or declined — sent to the applicant.  5. A "we received your request" acknowledgement, so someone who applies knows it arrived.

The free plan used here needs no domain of your own — you confirm a sender address with a six-digit code and can then email anyone, 300 times a day.

Without it: nothing breaks. You just check the dashboard yourself instead of being told.

Package downloads first run only

If a project needs extra libraries, they are installed the first time it starts rather than at upload. That needs the internet and can take a few minutes; after that it never repeats.

What to back up

All of it is plain files in one folder, readable in any text editor. Copying that folder is a complete backup — there is nothing else to export and no database to dump.

Files to include in a complete backup
WhatWhat it holds
AccountsUsernames, passwords, roles, and who has been approved.
Project listEvery project: name, kind, where its files are, who owns it, whether it is approved.
Project foldersThe actual uploaded files, one folder per project.
Lock passwordsUsernames and passwords for any locked projects.
Email settingsWhich service to use and the keys for it.
LogsWhat happened, including whether each email went out.

The accounts file contains passwords in plain text. Treat the whole folder as private: do not put it in a shared drive, and do not commit it to a code repository.

Good to know

The places where the app behaves in a way you might not expect. Each of these is a deliberate decision, but none are obvious from the interface.

Passwords are stored as plain text. Anyone who can read the accounts file can sign in as anyone. Keep the folder private, and don't reuse a password you use elsewhere.

Sign-in codes are not stored anywhere. A new user's six-digit code is emailed to them and kept only in the running program's memory, as a scrambled fingerprint rather than the digits themselves. Restarting the manager forgets any outstanding code — harmless, because they only last ten minutes and asking for another is one click. Copying the accounts folder to another machine gets you the accounts, never a usable code.

Signing in does not survive a refresh. The session lives in the page, not in a cookie, so reloading signs you out and every action is re-checked from scratch. Two browser tabs are two separate sessions — more on that.

Locking a project hides buttons; it does not hide the site. Anyone who already has the address can still open the project. Lock stops the dashboard's controls being used — it is not a way of keeping people off the link.

Approval emails are sent while you wait, and the app tells you the truth. If the mail service rejects a message, the dashboard turns amber and gives the reason instead of reporting a success that did not happen. The account is still approved — you just know the applicant was not told, so you can tell them yourself.

Emails sent from a gmail.com address carry no digital signature, so some will be treated as suspicious and land in spam. Sending from an address on a domain you own fixes it.

The last administrator cannot be removed, and neither can the one removing themselves. The guard is deliberate, so the dashboard cannot end up with nobody able to administer it. The built-in super admin goes further and cannot be removed by anyone at all — see roles and permissions.

Deleting a project can delete its folder. There is a checkbox for it, and it starts unticked — unticked removes only the entry and leaves the files on disk.

Running a second manager side by side is supported but has to be told which one it is, so the two never fight over the same ports or the same projects.
